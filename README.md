# TaskTrace

TaskTrace is a React Native + Expo Router client for checklist execution and action history. This stage contains the client foundation and Supabase email/password authentication.

## Setup

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env` and set `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` to the public Supabase values. Never use `service_role` in the client.

3. Start Expo:

   ```bash
   npm run start
   ```

In the output, you'll find options to open the app in a

- [development build](https://docs.expo.dev/develop/development-builds/introduction/)
- [Android emulator](https://docs.expo.dev/workflow/android-studio-emulator/)
- [iOS simulator](https://docs.expo.dev/workflow/ios-simulator/)
- [Expo Go](https://expo.dev/go), a limited sandbox for trying out app development with Expo

Web: `npm run web`. Android: `npm run android` (requires an emulator/device or Expo Go).

## Auth

`AuthProvider` restores the persisted Supabase session, subscribes once to auth state changes, and exposes sign-in, sign-up, sign-out, reset request, and password update operations. Route group layouts redirect authenticated users to `(app)` and unauthenticated users to `(auth)` while showing a bootstrap loading screen.

Profile rows are provisioned server-side by the `on_auth_user_created` trigger from migration `20260903000000_profile_provisioning.sql`; registration sends `raw_user_meta_data.display_name`.

The single Supabase client is in `src/lib/supabase/client.ts`. It uses Expo SecureStore for persistent native sessions and browser-compatible storage on Web. Database types are generated with `npm run gen:types` using `SUPABASE_DB_URL` or a linked `SUPABASE_PROJECT_ID`.

Apply all migrations before testing auth. Configure the reset callback URL generated by `expo-linking` (scheme `tasktrace`) in Supabase Auth URL settings; add the web origin used by Expo during local development. Native recovery links are consumed by `AuthProvider` and establish a recovery session before the reset screen is shown.

For a hosted release, enable Auth's leaked-password protection in the Supabase Dashboard and keep `secure_password_change` enabled. These hosted Auth controls are not represented in database migrations. Review the Dashboard redirect allow-list and rate limits separately for each environment.

For EAS builds, define `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` in each EAS environment (`development`, `preview`, and `production`). These are public client values; never configure a `service_role` key in EAS or the app bundle.

## Validation

Run `npm run typecheck`, `npm run lint`, and `npm test`. SQL security suites require a running local Supabase stack and can be run with `npm run test:sql`. End-to-end registration, email confirmation, reset links, and profile provisioning require a configured Supabase project.

The root `tasktrace_schema.sql` file is a historical baseline only. Deploy the ordered files in `supabase/migrations/`.

### Other setup steps

- To run linting, use `npm run lint`.
- To run the SQL security suites, start Docker/Supabase and use `npm run test:sql`.
